# Clawd Jump — 품질 향상 계획 (2026-09-22)

목표: **상용 수준의 캐릭터·배경 아트**, **묵직한 타격감**, **고수준 BGM/SFX**.
제약: **캔버스 기반 유지**, **외부 라이브러리·애셋 최대 활용**, **60fps 부드러움과 쾌적한 조작감은 절대 후퇴 금지**.

## 0. 현재 상태 진단 (사실 확인 완료)

| 항목 | 현재 |
|---|---|
| 본체 | `frontend/index.html` 5,975줄 단일 파일, 외부 의존성 0, `file://`에서 동작 |
| 렌더 | Canvas 2D, 640×360 논리 해상도, 16px 타일, `image-rendering: pixelated` 업스케일 |
| 루프 | `frame(now)` (L5955) — `STEP = 1/60` 고정 스텝 + `MAX_STEPS = 5` 클램프, 렌더 분리 |
| 스프라이트 | `index.html` 내부 픽셀 문자열 배열 (32×48), 팔레트 키 매핑 |
| 오디오 | 오실레이터 + 공유 노이즈 버퍼 실시간 합성, 스텝 시퀀서 BGM |
| 배경 | 절차적 패럴랙스 5층 (L5019~), 정수 배율 스크롤, 창문 점멸·네온 flicker **이미 존재** |
| 타격 연출 | 파티클 burst + hitstop + 화면 플래시 **이미 존재** (L3902~) |
| 애셋 훅 | `assets/manifest.json` 로더 **이미 존재** (L3470~) — 아틀라스 프레임 + 오디오 큐 개별 폴백 |
| 검증 | `verify.mjs` 단정 883건, `shot.mjs` PNG 렌더러 (브라우저 없음) |

**핵심 발견 1 — 애셋 계약은 이미 깔려 있다.** `manifest.json` → 아틀라스 프레임명(`ninja/idle`,
`charger/attack` …) + 오디오 큐명(`slash`, `bladeKill`, `music` …) 규약이 `frontend/assets/README.md`에
문서화돼 있고, 프레임 단위/큐 단위로 개별 검증·개별 폴백된다. **외부 애셋 도입은 신규 설계가 아니라
빈 계약을 채우는 작업**이다. 이게 이 계획의 비용을 크게 낮춘다.

**핵심 발견 2 — `shot.mjs`는 `drawImage`를 모른다.** 가짜 ctx가 `fillRect`/`fillText`만 구현한다
(`shot.mjs` L30-34). `verify.mjs`는 `drawImage`를 blit 기록으로 받는다 (L127). 즉 **아틀라스로 넘어가는
순간 유일한 "눈"인 PNG 렌더러가 멀어버린다.** 이 박스에 브라우저가 없으므로, 이 도구 업그레이드는
아트 작업의 **선행 조건**이다.

**핵심 발견 3 — 배경을 offscreen 캐시로 바꾸면 검증이 깨진다.** 배경이 매 프레임 `fillRect`인 것은
성능 무지가 아니라 의도다 (L5020-5023: shot.mjs가 fillRect 스트림을 재구성하므로 offscreen 레이어는
보이지 않는다). 캐싱은 **헤드리스에서 직접 경로로 떨어지는 이중 경로**로만 허용된다.

## 1. 결정해야 할 아키텍처 (가장 중요한 갈림길)

### A안 — Pixi/Phaser로 전면 교체 ❌ 비권고
WebGL 배칭·필터·파티클을 공짜로 얻지만, 렌더 루프 소유권을 엔진이 가져간다.
→ **단정 883건 + `shot.mjs` 전량 폐기**. 브라우저 없는 이 환경에서 검증 수단이 0이 된다.
→ 결정론적 고정 스텝 물리(코요테/점프버퍼/턴부스트 튜닝값 전체)를 재검증 없이 이식해야 한다.
→ 요청하신 "60fps·쾌적한 조작감 유지"를 **증명할 방법이 사라진다**. 비용이 이득을 넘는다.

### B안 — 3층 하이브리드 ✅ **권고**

```
L3  연출층   WebGL 포스트 패스 (게임 캔버스를 텍스처로 1회 블릿)
             bloom(창문/네온) · 히트 시 RGB split + 방사 블러 · 비네트 · 스캔라인
             → 실패하거나 느리면 이 층만 끈다. 원본 화면 그대로 남는다.
─────────────────────────────────────────────────────────────────
L2  애셋층   아틀라스 PNG + manifest (기존 계약 확장)
             캐릭터 프레임 · 배경 레이어 이미지 · FX 시트 · 오디오 파일
             → 파일이 없으면 내장 픽셀 배열/신스로 폴백 (이미 구현됨)
─────────────────────────────────────────────────────────────────
L1  코어     Canvas 2D + 고정 스텝 (현행 유지)
             물리 · 판정 · AI · 카메라 — 883 단정이 계속 지킨다
```

**왜 이게 맞나**: 요청의 "캔버스 기반 유지"를 문자 그대로 지키면서, 외부 라이브러리는 *렌더 소유권을
빼앗지 않는 위치*에만 들어온다. 각 층이 독립적으로 롤백 가능하고, 60fps 회귀가 나면 어느 층이
범인인지 즉시 좁혀진다.

### C안 — L3 구현 수단으로만 Pixi 사용 (B안의 하위 선택지)
게임 캔버스를 Pixi `Sprite` 텍스처로 올려 `pixi-filters`(BloomFilter, ShockwaveFilter, RGBSplitFilter,
CRTFilter, GodrayFilter)를 재사용. 셰이더를 직접 쓰지 않아도 되는 대신 런타임 ~400KB가 붙는다.
→ **L3 착수 시점에 자체 GLSL 1패스 vs pixi-filters를 실측 비교하고 결정.**

## 3. 구현 단계

난이도 S(반나절) / M(1~2일) / L(3~5일) / XL(1주+) · 우선순위 P0(선행 필수) ~ P3(있으면 좋음)

### Phase 0 — 파이프라인·검증 기반  `난이도 M` `P0`
아트 한 장 넣기 전에 반드시 먼저. **이 단계 없이 시작하면 눈 감고 작업하는 것.**

1. `shot.mjs`에 **`drawImage` 지원** — PNG 아틀라스 디코드 후 blit 합성, 알파 블렌딩. *(P0 최우선)*
2. Vite 도입 + `vite-plugin-singlefile` → `dist/index.html` 단일 파일 산출물 유지
3. `verify.mjs` / `shot.mjs`의 `<script>` 정규식 추출 → **모듈 엔트리 로드**로 전환 (`__t` 테이블 규약은 유지)
4. **프레임 예산 계측 HUD** (`D` 오버레이 확장) — update/배경/엔티티/FX/포스트 구간별 ms
5. `npm run verify` = 883 단정 + PNG 굽기 + **프레임 예산 회귀 체크**를 한 번에

**완료 기준**: 아틀라스 프레임 1장을 넣고 `shot.mjs` PNG에서 그것이 **눈으로 보이는가**.

### Phase 1 — 캐릭터 애셋 상용화 (닌자 통일)  `난이도 L` `P1`
주인공/적 전원 닌자 계열로 재설계. 실루엣으로 구분되어야 하므로 색만 바꾸는 건 실패.

| 대상 | 컨셉 | 실루엣 구분점 |
|---|---|---|
| 주인공 | 남색 기 + 붉은 스카프, 카타나 | 가장 좁은 몸, 스카프가 속도를 표현 |
| Charger | **중갑 무사닌자** — 흑색 사슬갑, 대태도 | 가장 넓은 어깨, 느리고 무거운 실루엣 |
| Rusher | **경장 닌자** — 두건, 짧은 쿠나이 | 앞으로 기운 자세, 가장 얇음 |
| Warden | **수리검 투척 닌자** — 등에 탄대, 부채꼴 자세 | 낮은 무게중심, 정지 실루엣 |

1. 아트 조달: 자체 저작(`hero_sprites.py` 확장) vs CC0 팩 vs 혼합 → **§5 결정 필요**
2. 아틀라스 패킹 (free-tex-packer-core) → `manifest.json` 자동 생성
3. 포즈 13종(주인공) + 8종×3(적) 전량 교체, 프레임별 폴백 유지
4. `wallGrab` 클리핑 주의 — 아틀라스 프레임은 **클리핑되지 않는다**(`assets/README.md` 명시).
   벽 엿보기 포즈는 **잘리지 않은 상태로도 성립하는 아트**로 공급하거나 내장본 유지
5. 팔레트 루미넌스 단정 갱신 (하늘 밴드 40포인트 분리 규약 유지)

### Phase 2 — 배경: 정적 → 이동 → 조명 반짝임  `난이도 M` `P1`
요청하신 3단 진행을 그대로 단계화. 기존 정수 배율 패럴랙스 규약(서브픽셀 금지)은 **유지**.

1. **정적 이미지 레이어 도입** — 6층(별/스카이라인/중경/원경건물/근경벽/전경소품) PNG 교체.
   `layerLoop`의 정수 오프셋 로직은 그대로 쓰고 `fillRect` → `drawImage`만 교체
2. **움직이는 효과** — 흘러가는 구름·달 halo 호흡·전선 흔들림·빨래/현수막 펄럭임·
   비 또는 흩날리는 재 파티클·지면 물웅덩이 반사
3. **건물 내 조명 반짝임** — 현행 창문 점멸(L5142-5158)·네온 flicker(L5272)를 확장:
   창문별 개별 위상 + 실내 그림자 실루엣 통과 + 등불 3프레임 애니 + **L3 bloom으로 번짐**
4. offscreen 베이크는 **헤드리스 직접 경로를 남기는 이중 경로**로만 (§0 핵심 발견 3)

### Phase 3 — 묵직한 타격감  `난이도 M` `P0` ⭐ **체감 대비 비용 최저 — 여기서 시작 권장**
파티클·hitstop·플래시가 이미 있으므로 "추가"가 아니라 "층 쌓기".

1. **히트스톱 곡선화** — 현행 고정 프레임 → 피해량별 2/4/6프레임 + 복귀 이징
2. **임팩트 프레임** — 적중 1~2프레임 동안 피격체를 흰 실루엣으로 치환 (격투게임 관용구)
3. **FX 시트** — 참격 궤적·충격파·먼지·피격 스파크를 스프라이트 애니로 (현행 타원 arc 대체)
4. **스크린셰이크** — 트라우마(trauma) 감쇠 모델 + **정수 픽셀 스냅**(서브픽셀 흔들림 = 셰이더 지글거림)
5. **카메라 펀치 + 넉백** — 처치 시 카메라가 타격 방향으로 밀리고 복귀
6. **처치 슬로우모션** — 마지막 적/연속 처치에만, 0.12s
7. **Gamepad API 럼블** — 패드 연결 시에만, 짧게
8. L3 연동 — 적중 순간 RGB split + 방사 블러 1프레임

### Phase 4 — 오디오 격상  `난이도 M` `P1`
1. **Howler.js 도입** — 기존 `playCue` 폴백 구조를 유지하며 재생 백엔드만 교체
2. **BGM**: 사전 렌더 OGG 루프 + Howler ✅ **권고** / Tone.js 실시간 합성은 옵션
   → 이유: 60fps 사수. Tone.js 라이브 합성은 메인스레드 스케줄 비용이 붙는다.
   샤쿠하치·타이코·코토 편성의 야간 잠입 트랙, 인트로/루프 분리
3. **큐 확장** — 발소리(재질별)·착지·벽 등반·패링·경보. 현행 11큐 → 20+
4. **믹싱** — 거리 감쇠 + 스테레오 팬(적 위치), 타격 시 BGM 순간 덕킹, 데스 스팅어
5. `music`은 공급 시 내장 시퀀서를 **완전히 대체**(이미 구현) — 데스 시 즉시 컷 규약 유지

### Phase 5 — 60fps 사수 · 쾌적함  `난이도 M` `P0` (상시 게이트)
**품질 향상의 모든 PR이 통과해야 하는 관문.** 별도 단계가 아니라 Phase 0~4에 상시 병행.

**프레임 예산 (16.67ms)**
| 구간 | 예산 |
|---|---|
| update (물리·AI·판정) | 2.0ms |
| 배경 | 2.0ms |
| 월드 + 엔티티 | 3.0ms |
| FX·파티클 | 2.0ms |
| L3 포스트 패스 | 1.0ms |
| **여유** | **6.6ms** |

1. 파티클 **상한 + 오래된 것부터 폐기**, FX 동시 개수 캡
2. 아틀라스 단일 이미지 = drawImage 상태 변경 최소화, 스프라이트별 팔레트 스왑 제거
3. `dt` 클램프(`MAX_STEPS`) 유지 — 탭 복귀 시 시간 폭주 금지
4. **저사양 폴백** — 연속 프레임 드랍 감지 시 L3 자동 해제 → FX 감축 → 배경 레이어 축소 (자동 단계적 강등)
5. **옵션 메뉴** — 화질(고/중/저) · 화면 흔들림 강도 · 모션 감소 · BGM/SFX 개별 볼륨
6. **입력 지연 사수** — 키 입력→화면 반영 프레임 수를 단정으로 고정. 연출이 조작을 먹지 않게
   (특히 hitstop/슬로우모션 중 입력 버퍼링 유지)

## 5. 결정 필요 항목

1. **L3 구현 수단** — 자체 GLSL 1패스(가볍다) vs pixi-filters(빠르다, ~400KB)
2. **아트 조달 방식** — ⓐ 자체 저작(`hero_sprites.py` 확장, 스타일 완전 통제, 느림)
   ⓑ CC0 팩 채택(빠름, 실루엣 규약 재검증 필요) ⓒ 혼합(CC0 배경 + 자체 캐릭터)
3. **`file://` 단일 파일 실행성** — 유지(singlefile 인라인, 애셋도 base64 인라인 → 용량↑) vs
   포기(`dist/` 정적 폴더 + 로컬 서버 전제)
4. **BGM** — 사전 렌더 OGG(권고) vs Tone.js 어댑티브(긴장도 레이어, 60fps 리스크)
5. **크레딧 화면** — CC-BY 애셋을 쓸 거면 먼저 만들어야 함. CC0만 쓰면 불필요
6. **단정 883건의 운명** — 아트 교체로 픽셀 배열 단정 일부가 무의미해진다.
   삭제 vs 아틀라스 blit 단정으로 이관
